# Project Instructions

- Prefer separating responsibilities between Swift classes.
- Each file or class should generally handle one primary concern.
- Avoid mixing feature implementation and management logic in the same class.
- Use dedicated manager classes for domain-wide state or behavior (for example, card/deck management).
- Prefer protocols and explicit API methods for updates instead of broadcasting notifications.
- This is a guideline, not a strict SOLID rule: aim for cleaner separation without over-engineering.
