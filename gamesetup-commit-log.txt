Item 1: Game setup and initial state

Step 1.1 — Setup validation and game spawning
- Added EDGameSetupManager with supported player-count and duration validation.
- Added an ordinary setup-manager instance and startGame entry point.
- Spawned an ExecutiveDecisionGame with configured player count, duration,
  settings, first month, and setup state.
- Prevented external direct initialization of ExecutiveDecisionGame so creation
  goes through the setup manager.
- Prevented an individual setup manager from starting a second game while its
  active game is not over; a new game can start after gameOver. Separate manager
  instances are independent.
- Added tests for valid/invalid counts and durations, spawned game fields,
  duplicate-start rejection, restart after game over, and independent managers.
- Updated TODO item 1.1 to Complete.

Follow-up simplification:
- Removed the shared singleton, NSLock, and unchecked Sendable conformance.
- Setup manager lifecycle is instance-scoped; no concurrency guarantees are
  claimed or implemented.

Not completed in this step: starting cash lookup, opening market prices,
28-card raw-material supplies/certificates, and full game-session market setup.
